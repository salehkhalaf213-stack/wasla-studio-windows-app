# نسخة الويب الموحدة — WASLA STUDIO

هذه الحزمة هي نسخة المتصفح من واجهة WASLA STUDIO الموجودة في:
`WASLA_STUDIO_Desktop/src/index.html`
على فرع `feature/wasla-v6`.

## ما تم تجهيزه
- واجهة الويب من نفس ملف واجهة Windows، دون استبدال ملف تطبيق Windows.
- وحدات WASLA FINANCE الموجودة في المصدر، ومنها فواتير العملاء وضريبة القيمة المضافة وتصدير PDF.
- اتصال Supabase نفسه الموجود في التطبيق.
- إعداد Netlify في جذر المستودع (`netlify.toml`) لنشر مجلد `web-app` كموقع HTML ثابت.

## إعداد Netlify — بعد المراجعة
أنشئ Deploy Preview أو موقع Netlify منفصلاً أولاً:
- Repository: `salehkhalaf213-stack/wasla-studio-windows-app`
- Branch: `feature/wasla-web-v6`
- Base directory: اتركه فارغاً (جذر المستودع).
- Build command: اتركه فارغاً.
- Publish directory: `web-app`.

لا تربط هذه الحزمة بالموقع الحالي ولا تغيّر إعداداته قبل اختبار النسخة الجديدة.

## إعداد Supabase بعد معرفة رابط النشر
في Supabase Auth > URL Configuration:
- أضف عنوان النشر الفعلي إلى Site URL أو Redirect URLs وفق سياسة المشروع.
- لا تستخدم عنواناً تخمينياً؛ خذ الرابط الذي يعرضه Netlify بعد إنشاء Deploy Preview.

## اختبارات ما قبل التحويل
1. تسجيل الدخول والتحقق من Cloudflare Turnstile.
2. تحميل المؤسسة الحالية وبياناتها مع التحقق من عزل المؤسسات.
3. مراجعة الأدوار والصلاحيات.
4. فتح فواتير العملاء، وإنشاء مسودة اختبار فقط في مؤسسة اختبارية.
5. فحص احتساب VAT والقيد المحاسبي دون إنشاء قيود تجريبية في المؤسسة الحية.
6. تصدير PDF من نافذة الطباعة وحفظه.
7. اختبار الموظفين والمشاريع والتكليفات والنسخ الاحتياطي.

## تنبيه
إنشاء هذه الحزمة لا ينشرها تلقائياً على Netlify. لم يتم تعديل `main` أو إعدادات الموقع الحالي أو بيانات Supabase أو حسابات المستخدمين. لا تعتبر النسختين متطابقتين على الموقع العام حتى يكتمل Deploy Preview والاختبار ثم يتم اعتماد النشر.
